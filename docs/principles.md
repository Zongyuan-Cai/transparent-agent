# 目标与原则

Transparent 的承诺是用户可以检查每次送给 API 的内容、API 实际返回的内容以及工具参数、结果和副作用。终端摘要不是透明记录本身。

- 请求保存最终 system、历史、工具 schema、模型和生成参数；不能只记用户问题。
- provider 同时保存实际 HTTP body、响应字节和归一化响应。服务端未返回的内部状态不在承诺范围。
- 工具保存原始参数、完整结果、回填结果、失败/取消、耗时和截断事实。
- 记录关联 session/run/request/call，并有递增 seq；时间戳不代替因果顺序。
- 认证 header/URL 参数脱敏，正文保持完整；脱敏例外公开说明。
- trace 失效后停止运行；普通 UI/观察者异常不阻断核心。

核心不打印、不导入 TUI；provider 不执行工具；tool 不知道模型；skill 不自动执行脚本。模型选择工具和步骤，runtime 施加明确步数、超时和环境边界。工具串行，不隐式重试副作用。

默认 CLI 保存 trace 和 session，无需用户写 sink。保持现有 TUI 输入、输出、中断方式，只加必要入口。文档、代码、离线验收必须一致。
